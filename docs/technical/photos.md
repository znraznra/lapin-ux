# Photos (`lapin-ux-photos`)

An offline picture app (#74). Nothing leaves the computer: no cloud, no accounts, no network.

## Two views

- **Gallery**: follows the person's light or dark theme (#200). A toolbar on top, an optional side bar (Gallery, Favorites, Recents, then Media types: Screenshots, Animated GIFs, and Hidden, then your albums) and the grid.
  - Toolbar: side bar toggle, **Source** (all folders, or Pictures, Downloads, Desktop, Documents, shown only when they exist), **Group** (Years, Months, Days, All), a square or own-proportions grid toggle, a size slider, **Select**, and a More menu (Slideshow and Look for new pictures; **Stop looking in this folder** for an added folder; **Rename this album** and **Delete this album** inside an album).
  - The size slider has seven positions: six grid sizes, then a reel as the last one. The reel shows one large photo with the others in a strip below; clicking the large photo opens the viewer.
  - **Select** shows a tick on each tile you click. Click selects, Shift+click selects a range, Ctrl+click toggles one (adds it if it is not selected, removes it if it is), Ctrl+A selects every tile loaded so far (up to the current load limit, including ones scrolled out of view, and never a photo the list does not show, so nothing unseen can be moved to the Recycle Bin), Esc clears. While photos are selected the toolbar offers Select all, favorite or unfavorite, and move to the Recycle Bin (asks first, uses `gio trash`).
  - **Recents** shows the last three days.
  - **Screenshots** shows pictures in a folder or with a file name starting "Screenshot". **Animated GIFs** shows `.gif` files.
  - **Hide** (in the selection toolbar) moves the selected photos out of every section except **Hidden**. In Hidden the same button reads **Unhide**. Without a password, hiding keeps the file where it is and only changes what Photos shows. With a password (see below), hidden pictures are encrypted. Favorites, albums and Hidden are saved under each photo's real (canonical) name, so a symlink or `..` spelling of the same file matches the same entry.
- **Viewer**: one photo at a time with a floating toolbar (back, previous, next, favorite, slideshow play, full screen, file name) and a filmstrip of the nearby photos. Left and Right step through the list, Esc goes back to the gallery.

Opening a picture from Files (`lapin-ux-photos %f`) goes straight to the viewer, also when the picture is outside the scanned folders.

The side bar, source, group, grid style and size are remembered in `~/.config/dev.lapinux.Photos/settings.json` (the list of added folders is separate, in `folders.json`). Each one is saved on its own under a lock, so two open windows never write back an older value of a setting the other just changed.

**More actions** (#202): Rename (keeps the picture's place, thumbnail and star, and never replaces another file), Delete (asks first, then moves the picture to the Recycle Bin with `gio trash`, never a permanent delete; the viewer moves to the next photo, or the one before it, or back to the gallery when it was the last) and Open file location.

## How it works

- The scan walks the four folders in the background, up to 5 levels deep, skipping hidden folders, and stops at 20,000 pictures. Starred pictures outside those folders are added on top of that limit, since they are the person's own choice. A starred picture whose real file has no picture extension (a link named `a.jpg` pointing at `raw-file`) is kept when its first bytes are a supported format. An empty section still shows the read-error, stopped-early and could-not-save notes, and says "could not be read" only when a folder really failed. Formats: JPEG, PNG, WebP, BMP, GIF.
- Tiles are 100 to 250 px high (squares or the photo's own proportions, kept between 0.6 and 2 times the height), decoded four at a time off the UI thread, upright by their EXIF rotation. Tiles load as you scroll: 200 to start and 200 more each time you scroll near the bottom (about 92 MB of pixels for a full set of 240 x 240 RGBA tiles, and thumbnails already loaded stay in memory when you change section, so the limit is per view, not for the whole cache, which can grow with every section you open). Changing section starts again at 200. The grid is not virtualised yet. Only the tiles near what you are looking at (about 150 either side) keep their thumbnail in memory: the others are dropped and decoded again when you scroll back. Changing the source folder starts the grid again at 200.
- The full picture is decoded when opened and scaled down once if it is larger than 3840 px on either side.
  - **Albums**: the side bar lists them with **New album**. Select photos, then **Add to album** in the toolbar picks an album or makes a new one (a name box appears under the toolbar; Esc closes it). Inside an album, the remove button takes the selected photos out of the album only, never deletes files, and **More > Delete this album** removes the album and leaves the photos alone.
  - **Slideshow**: **More > Slideshow** in the gallery, or the play button in the viewer. It starts at the open photo (or the first selected one in gallery order, or the first shown). A photo opened from Files that is outside the section plays on its own, as a list of one. It follows what the current section shows, moves on every 4 seconds (More > Slideshow speed steps through 2, 4, 8 and 15, kept in `settings.json`) and starts over after the last photo. The button turns into pause, and Esc or Back to the gallery stops it. Left and Right still work while it plays.
  - **Add folder**: the folder drop-down in the toolbar has an **Add folder...** item, which opens the usual folder dialog. The folder is searched like Pictures, Downloads, Desktop and Documents (a newly added folder is scanned first and has its own budget, so a large Pictures folder cannot crowd it out), shows up in the drop-down under its own name, and is remembered in `folders.json`. **More > Stop looking in this folder** forgets it again (the folder itself is not touched).
  - **Rename this album**: in an album, **More > Rename this album** shows the name box with the current name. A name that another album already uses is refused.
  - **Password for Hidden (the vault)**: in Hidden, **More > Set a password** (later **Change** or **Remove the password**). Setting a password makes an encrypted vault and moves the pictures already hidden into it. From then on Hide moves a picture into the vault (the original file is deleted once the encrypted copy and the index are saved) and Unhide puts it back in the Pictures folder under its old name (never over a file that is there). With a password set, Hidden shows a lock screen until it is typed and locks again when you leave the section. A forgotten password cannot be recovered: the set-password box says so. Inside the vault there are no favorites, albums, Recycle Bin, turn or edit; the only way out is Unhide. **Remove the password** (needs Hidden open) takes everything out, puts the pictures back on the plain Hidden list and deletes the vault; if one picture cannot come out, the vault and password stay.
    - Crypto (`vault.rs`): Argon2id (19 MiB, 2 passes, 1 lane, a random salt) turns the password into a key that seals a random data key (ChaCha20-Poly1305). Each picture is its own ChaCha20-Poly1305 file, `<id>.bin`, with the id as associated data, so a file swapped or renamed is refused. The list of pictures (name, date) is sealed the same way, so file names are not readable on disk. A cost stored in a changed key file is bounded before it is used. Pictures are decrypted in memory only, for thumbnails and the viewer; nothing readable is written to disk. The key is held in memory after the first unlock so Hide works from other sections and is dropped when the password is removed or the program ends. It does not protect against someone who can read the memory of the running program.
    - Files: `~/.local/share/dev.lapinux.Photos/vault/` (key file, sealed index, `<id>.bin`). Kept in the data folder, not the config folder, so a settings reset never destroys the pictures.
  - **One name per picture**: hidden photos, the gallery filter and the scan's duplicate check use the picture's canonical path (symlinks and `..` resolved), so a symlink or `..` path to a hidden picture cannot show it. A second hard link to the same file has its own path and is not matched: hide each link you want hidden. Entries saved under the old spelling still count.
- Favorites and hidden photos are saved as path lists in `~/.config/dev.lapinux.Photos/favorites.json` (under `XDG_CONFIG_HOME` when that is set; the Hidden recovery messages show the real path) and `hidden.json`, each written under its own lock file and swapped in atomically. Albums are a name to path-list map in `albums.json`, saved the same way (`albums.lock`). Added folders are a path list in `folders.json` (`folders.lock`).
- Favorites are saved in `favorites.json`. A failed save is logged and never ends the program (#174).

- Slideshow speed: More > "Slideshow speed" steps 2, 4, 8, 15 seconds, saved as `slide_secs` in `settings.json`. The viewer toolbar has a Full screen button; leaving the viewer leaves full screen.
- Tiles load as you scroll: the grid starts with 200 and adds 200 more each time you scroll near the bottom, so the old "Showing the newest 400" line is gone. Changing section starts again at 200. Only the tiles near what you are looking at (about 150 either side) keep their thumbnail in memory; the others are dropped and decoded again when you scroll back, so a very long scroll no longer grows memory. Changing the source folder also starts the grid again at 200.
- Turn left / Turn right in the viewer toolbar rewrite the file turned a quarter (a failed turn shows a note under the toolbar, cleared on the next try) (JPEG, PNG, WebP, BMP; not GIF). The camera's rotation tag is baked in and dropped, the write goes through a temporary file that is created exclusively (`create_new`, a dot-prefixed random name beside the picture, owner-only while it is written, so a leftover file or a planted link is never written through), given the picture's own permissions back, synced, renamed over the original and the folder synced so the rename survives a crash, and JPEG is compressed once more.
  - A picture that is a symbolic link stays a link: the real file it points to is the one that is replaced, never the link.
  - The file must really be the format its name says, and moving pictures (an animated PNG, an animated WebP) are refused with a note, since a turn would flatten them to one frame. The image decoder itself is asked whether the file is animated, so a marker placed late in the file cannot get past the check, and a file the decoder cannot inspect is not treated as a still picture.
  - If the folder cannot be synced after the swap, the turn is kept (the file is already replaced) and a note says it may not survive a power cut.
  - Turns and edits run one at a time, under one lock file (`transform.lock`), so two Photos windows cannot rewrite the same picture at once.
- Edit in the viewer: the pencil button shows Brighter, Darker, More contrast, Less contrast, Black and white, and Crop square, 16:9 or 4:3 (the middle of the picture is kept). Every edit is saved as a copy, "name (edited).ext" beside the original (or "(edited 2)" and so on, never over an existing file), and the copy opens. Only a copy made in this Photos session is edited in place, so repeated tweaks do not pile up files. Photos remembers the copy's file identity (device and inode), and if another file has since been put under that name, or the file is a link or a file that merely has "(edited)" in its name, it is never overwritten: it gets a copy like any other picture. JPEG, PNG, WebP and BMP; not GIF, and the same format and moving-picture checks as Turn apply. The write goes through a temporary file that is created exclusively (a leftover or planted link is never written through), and a new copy is hard-linked into place (a plain rename only where links are not supported and the name is free), so it can never replace a file that appeared in the meantime. If the name is taken after it was chosen, the next free name is tried (up to 8 times). A copy of a hidden picture is hidden too: its name is added to the hidden list before the copy is published. The list is written, synced and its folder synced before the copy appears, and if that fails nothing is published, so a hidden picture never has a visible copy, not even briefly. A name that was added but never used (taken meanwhile, or the publish failed) is taken off the list again. A hidden list that cannot be read stops the edit. Turns and edits share the `transform.lock` described above, and a folder sync failure after publishing shows a note instead of an error.
- Rotate (viewer): follows a symlink to the real file and replaces that, so the link stays a link and the picture keeps its name in Favorites, albums and Hidden. If the folder cannot be flushed after the swap, the new picture is still shown and a note says the disk has not confirmed it yet.
- Favorite toggle (viewer): the star reads the picture's canonical name fresh when pressed, so a link retargeted since the scan stars and unstars the file it points to now.

## Coexistence

Photos writes only its own `dev.lapinux.Photos` folder, so nothing is added to `items()` in `tools/lapin-ux-uninstall`. It replaces no COSMIC package. The Hidden vault lives in `~/.local/share/dev.lapinux.Photos/vault/`; `lapin-ux-uninstall` never touches that folder, because it holds the person's own pictures, and uninstalling Lapin UX must not delete them. (If the Photos app is removed the pictures stay encrypted there.)

- Progress for vault jobs: while Hide or Unhide with a password, setting, changing or removing the password, or checking the password runs, a bar under the toolbar (in the gallery and in the viewer) says what is happening and counts "12 of 340" pictures. A step is counted after each picture is finished (two atomic counters read every 200 ms). Checking the password has no count, so its bar just moves. A second Hide or Unhide pressed while one runs shows a note instead of starting.
- Hide from the viewer: an eye button in the viewer toolbar hides the open picture (in Hidden it unhides it) and then shows the next picture, or the previous one if it was last, or goes back to the gallery if it was the only one. With a password the move runs as a vault job and the viewer moves on when it finishes; the button is off while a job runs. Hiding into the vault still needs the password typed once (Hidden), as in the grid.
